**Owner:** Suraj Kumar

**Goal:** Earn references that help relevant people discover original guides, tools and genuine professional work.

## Reporting rules

A domain in this document is a **candidate**, not a backlink. Creating a profile, sending a pitch, sharing a post or submitting a product does **not** count as a published backlink until the destination page is live and its link to `https://heysuraj.com/` (or a relevant subpage) has been verified. Editorial sites choose what to accept. Some links may be nofollow, user-generated or otherwise not pass ranking signals; that is not a reason to manufacture links.

Google prohibits automated link schemes and low-quality directory links for manipulating rankings. Every link must provide genuine context to readers. Do not buy dofollow placements, spam community replies, or publish duplicate guest posts solely to meet a quota. Platform policies can change; review current contributor terms before submitting.

## Outreach stages

1. **Confirm fit.** Read the publication's current policies, subject categories and examples. If there is no appropriate route, skip it.
2. **Bring an asset worth citing.** Strong candidates are the full GitHub Pages setup guide, a well-documented lead-quality model, the LP LeadOS and SEO audit project write-ups, or an original reproducible dataset. A link request without value is unlikely to succeed.
3. **Pitch one relevant idea.** Explain the reader problem, the proposed original contribution and why you are qualified to write it. Don't promise guest posts that merely repeat what is already on the site.
4. **Record reality.** Store submitted date, editor response, published URL, link target, link qualification where visible, and a recheck date. Never call a submission a backlink.
5. **Learn.** Use genuine referral visitors, editorial relationships and reader engagement as success criteria, not a fixed number of links.

## Short example pitches

**Web-development publication:** “I recently built and indexed a fully custom GitHub Pages personal site with custom DNS, HTTPS, static article URLs and an accessible motion system. I'd like to contribute a reproducible walkthrough of the things that broke, how I verified each step and how readers can avoid misleading indexing assumptions. I can provide a working code example and screenshots.”

**Growth publication:** “Many small service businesses optimise ad spend against form clicks without defining whether an enquiry is valid or qualified. I'd like to write a practical, evidence-led guide to event definitions, deduplication, accidental call taps and the quality feedback loop, including a clearly labelled illustrative funnel.”

**Developer/founder community:** “I'm building a lead-research and an SEO-audit workflow, and the difficult part has been source evidence and data reliability rather than the dashboard. I've documented the open questions, constraints and current status. I'd value feedback on the approach and can share implementation notes if they're useful.”
