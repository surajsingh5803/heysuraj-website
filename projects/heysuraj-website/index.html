PROJECT NOTE / LIVE PERSONAL WEBSITE

HeySuraj.com.

A free-hosted, interactive personal website that documents marketing experience, independent technology projects and original thinking without relying on a paid CMS.

SURAJ KUMARLIVE PERSONAL WEBSITELAST REVIEWED 2026-11-14

Why I created a personal digital headquarters

I wanted a single place where my professional experience, independent ventures, AI experiments and creative interests could belong together. A conventional résumé is useful but too narrow for work that moves between marketing, software ideas and content. A personal website gives me a stable identity that is not tied to one employer, social platform or service offering.

The name HeySuraj is intentionally broad and personal. It can represent current work and future experiments without requiring a new brand every time an interest changes. The website is designed as a living archive, not a fixed campaign landing page. It should help someone understand what I actually work on and decide which subject or project they want to explore.

The decision to use GitHub Pages

GitHub Pages allowed me to host a static website on a custom domain without buying a conventional hosting plan. The source remains readable HTML, CSS and JavaScript, so the site is transparent to maintain and easy to deploy from a repository. That simplicity is part of the design. Not every interesting interactive experience requires a large framework, database or subscription.

Getting the domain live involved configuring DNS, verifying the custom hostname and waiting for HTTPS provisioning. Google Search Console verification, the sitemap and URL Inspection then helped me understand the difference between a site being live, crawlable and actually indexed. The full process is documented in the practical SEO on GitHub Pages guide.

A bold visual system with practical controls

The homepage uses a dark interface, lime accent, orbital artwork and a photographic portrait. Rather than relying on a single permanent visual treatment, it offers several curated colour worlds and motion styles. Those controls are meant to be enjoyable without making navigation or reading difficult. Reduced-motion support and responsive layouts are part of that requirement.

Project cards and the interactive lab help visitors explore different parts of my work, but important long-form pages are ordinary crawlable documents. A good design should make the information more inviting, not hide it behind visual effects. This balance is especially important on a personal site where trust and clarity matter as much as appearance.

From surface-level cards to detailed evidence

The initial website was deliberately compact. As the project evolved, it became clear that brief cards could introduce a venture but could not explain the questions, architectural decisions, setbacks and lessons behind it. The second stage therefore adds standalone About, Work, Project and Writing pages that visitors can explore directly and that search systems can interpret independently.

The content strategy is to separate published work from plans. A prototype should not be described as finished software. A writing idea should not appear as a published 4,000-word guide until it actually exists. Claims about results should be supported by appropriate evidence. This makes the website more useful as it expands because a visitor can distinguish what has been done from what is still being explored.

SEO as a foundation, not a ranking promise

The website uses titles, descriptions, canonical URLs, sitemaps, structured data and readable internal links. Those elements help search engines discover and interpret content, but they do not guarantee prominent rankings. I also use a consistent personal identity across the site and linked professional profiles. Original guides and detailed project explanations should gradually provide stronger evidence of what the site is about.

The decision to keep important content in static HTML improves resilience when JavaScript fails and simplifies crawlability. Technical optimisation remains an ongoing process: test mobile performance, confirm new pages are included in the sitemap, review Search Console indexing reports and revise content when its value or accuracy changes.

What the site should become

I want HeySuraj to be useful beyond displaying a biography. It should hold technical explanations that someone can follow, honest reflections about building products, examples of marketing analysis and links to actual work. Over time, each new piece should make the existing pages easier to understand and give someone a good reason to return.

The long-term goal is not more animations or more words for their own sake. It is a personal publishing system that makes curiosity visible and learning transferable. That is why the guiding line remains: A mix of ventures, experiments and tools — because the best way to learn is to build.
